为什么原型做成独立的隐藏页面，而不是直接改 `works.html`：

- 可以直接发布到 `mtdo.cn`，老板看到的是正式站上的真实作品，不是本地样例。
- 访客看到的网站完全不变，没有风险；老板不满意可以随时改，不需要回滚。
- 确认之后再一次性替换旧页面、删除旧代码（步骤 5），避免「做一半的新功能 + 删一半的旧功能」同时上线。

## 三、需求 04：禁止下载

### 实现方式

1. **新增公共脚本 `image-guard.js`**，在所有公开页面（首页、作品、作品详情、关于、联系、两个原型页）加载：
   - 在图片上屏蔽右键菜单（`contextmenu`），访客看不到「图片另存为 / 复制图片」。
   - 屏蔽图片拖拽（`dragstart`），并给页面上已有和之后动态插入的图片统一加 `draggable="false"`。
2. **样式层保护**（`styles.css`，只作用于带 `data-image-guard` 的公开页面）：
   - 图片设置 `-webkit-touch-callout: none`（iOS 长按不弹出「存储图像」）、`user-select: none`、`-webkit-user-drag: none`。
   - **透明保护层**：作品卡片、作品详情大图、查看器大图的 `<img>` 设为 `pointer-events: none`，点击、长按、右键都落到外层容器上，浏览器就不会把它识别为图片。现有的点击逻辑改为绑定在容器上。
3. **后台页面不受影响**：后台不加载 `image-guard.js`，管理人员照常查看和下载原图。
4. **服务端保持现状**：原图从不对外；公开图片只有展示图和缩略图，签名链接 10 分钟有效。

### 边界（需要老板知道）

- 截屏、录屏、开发者工具无法阻止，这是所有网页的共同限制，需求文档里也已说明。
- 展示图分辨率（问题 17，建议长边 2000–2500 像素）还没定。目前沿用现有展示图尺寸，老板确定后改上传时生成展示图的尺寸即可。

## 四、需求 06 + 07：原型设计

### 4.1 数据来源

- 直接用现有公开接口 `/api/archive/images`：正式站读 Supabase 已发布作品，本地读 SQLite 样例。原型**不改数据库、不改接口**。
- 系列映射沿用 v1.7.0：此间留彩 = `concrete`，此间留灰 = `abstract`。
- 英文系列名（问题 20）未定，原型暂用上传页已有的 **Colour / Grey**。
- 正式站的图片链接 10 分钟过期：浏览页在图片加载失败时自动重新拉取作品列表，长时间停留也不会出现破图。

### 4.5 展厅场景的技术方案

- **纯 CSS + SVG 实现，不用 WebGL**：展墙纹理用 SVG 噪声滤镜按比例生成，任何分辨率都清晰，几乎不占流量；低性能设备不需要单独降级。
- **空间感**：画面上部约 4/5 是展墙，下部是地面和踢脚线；地面上有射灯的反光。
- **作品悬挂**：按作品比例在展墙视觉中心放到最大，四周保留呼吸空间；投影方向和灯光一致。
- **灯光**：射灯光斑落在作品上方并洒到墙面，四周自然暗下；鼠标移动时光影有极轻微的视差，像观众在挪动脚步。
- **换作品**：灯光渐暗、作品替换、灯光渐亮，模拟展厅换展；手机端则是跟手的左右滑动。
- **预加载**：始终预加载前后各一张展示图，翻页无等待。

## 五、需求 08：Mac mini 数据服务（设计，待硬件就绪）

需求文档已确定方向（方案 B：数据库和图片都在 Mac mini，自建后台登录，逐步停用 Supabase）。实施时按以下顺序：

1. **服务器侧先抽出数据接口层**：`server.py` 里所有 Supabase 调用（作品、上传、询价、后台登录）收拢到一个数据提供者接口后面，先用 Supabase 实现，行为不变；之后新增 Mac mini 实现，切换只改配置。这一步不依赖 Mac mini，但改动面大，要在 Mac mini 就绪前一个阶段开始，并补齐回归测试。
2. **Mac mini**：PostgreSQL + S3 兼容对象存储（如 MinIO，原图 / 展示图 / 缩略图分桶）+ 内部数据接口，只接受网站服务器的请求。
3. **连接**：WireGuard 或 Cloudflare Tunnel，Mac mini 不对外开放端口。
4. **自建后台登录**：白名单账号、密码 + 两步验证、找回密码邮件继续走 Brevo。
5. **迁移与停用**：作品、图片、询价从 Supabase 迁到 Mac mini，核对无误后停用 Supabase。
6. **离线兜底**：服务器缓存公开作品数据，图片走 CDN；Mac mini 短暂离线时访客照常浏览，询价先暂存在服务器。

开始前需要项目负责人提供：Mac mini 的远程登录方式、宽带运营商与上行带宽、硬盘与备份设备、是否接受 Cloudflare CDN（需求文档问题 22、23）。
